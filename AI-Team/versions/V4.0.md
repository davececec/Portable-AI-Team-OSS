# V4.0.0 迁移说明

- 日期：2026-11-06
- 类型：升级（自愈式升级框架）
- 目标：让团队在任意目录深度下都能自我定位、自我修复，升级不再靠手工改路径。

## 变更

1. **项目根显式化**：`capsule.py enable` 新增 `--project <项目根>`。解析顺序：显式参数 → 向上查找 `.portable-ai-team.json` → `.git` → `AGENTS.md` + `.agents/.codex` → 报错不猜。启用成功后写入项目根标记文件 `.portable-ai-team.json`。
2. **模板占位符化**：`AI-Team/bridges/**` 与 `AI-Team/adapters/**` 中所有胶囊路径改为 `{{CAPSULE_PATH}}`，启用时按真实相对路径渲染。重新启用即可修复被手改乱的桥接文件。
3. **enable 幂等**：AGENTS.md / CLAUDE.md 只替换标记区块内部，区块外项目自定义内容原样保留；已管理桥接文件原地覆盖，不再生成 `portable-ai-team-2.md` 之类的副本。
4. **版本档案**：`AI-Team/versions/manifest.json` 记录版本序列；每个版本有迁移说明；项目级 `团队状态.json` 追加 `upgrade_history`。
5. **doctor 体检**：新增项目根、版本一致、版本目录、模型路由、桥接路径解析、重复锚点、记忆容量检查；缺少 `LLM配置.json` 不再判失败。
6. **模型档位路由**：角色按 `fast / standard / high-risk / vision` 档位选择模型，具体模型 ID 集中在 `AI-Team/config/model-tiers.json`；模型换代只改该文件。
7. **升级脚本重写**：`upgrade_carry.ps1` 不再逐文件替换字符串，改为"保留旧版目录 + 放入新版胶囊 + 继承旧安装清单与本地私有状态 + 调用新版 enable 重新渲染全部桥接 + 记录升级历史"；失败自动回滚。

`capsule_id` 是团队记忆谱系标识，跨升级保持不变；判断功能版本以 `team_version` 为准。

## 升级步骤

```powershell
# 在业务项目根目录执行；新胶囊可来自母版或任意已解压目录
powershell -File <旧胶囊>\AI-Team\upgrade_carry.ps1 `
  -NewVersion V4.0 `
  -OldVersion V3.0 `
  -NewCapsulePath <本地路径>\Portable-AI-Team-master `
  -ProjectRoot <项目根>
```

`-ProjectRoot` 可省略：从项目内旧胶囊运行时脚本会自动向上定位；从项目外的母版运行时必须显式传入。

## 回滚

- 旧版本目录默认原地保留，写明 `UPGRADED_TO_V4.0.md`。
- 需要回退时在新胶囊目录执行 `python AI-Team/capsule.py enable --project <项目根> --force` 切换到旧版胶囊的 `enable` 即可。
- 升级失败时脚本会把新版目录移到 `.failed-upgrade-<时间戳>`，旧桥接保持不变。
